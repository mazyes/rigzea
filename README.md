# Rigzea Blueprint

## System Overview

Rigzea is a real-estate CRM for agents in Georgia (rentals and sales). It is plain HTML, CSS and JS with
no build step beyond asset stamping. The static site in `rigzea/` is deployed to Vercel (project
`rigzea-website`, live at https://rigzea.com) together with the serverless functions in `api/`. All data
lives in the Supabase project `cuioodytwyzykqlrjfej`; access is enforced by row level security and
RPCs, so the browser only ever holds the public anon key. Working rules for agents are in
[CLAUDE.md](./CLAUDE.md); copy rules are in [voicetone.md](./voicetone.md).

## Local Interface & Invariants

- `serve.js`: `npm run dev`, a static server for `rigzea/` on http://localhost:3000 (no `/api`).
  `npm run dev:full` runs `vercel dev` for the site plus `/api` and the `/p/<slug>/` rewrites.
- `vercel.json`: `outputDirectory` `rigzea`, `buildCommand` (stamp assets, generate sitemap),
  per-function `includeFiles`, `/p/` redirects and rewrites, security and cache headers, daily cron.
- `.vercelignore`: keeps tests, scripts (except the two build scripts), docs and the `rigzea/**/README.md`
  contracts out of the deployment.

## Subdirectories & System Boundaries

- rigzea: [./rigzea/README.md](./rigzea/README.md) - the public static site: landing page, the CRM in
  `app/`, shared `js/` (`window.R`), public listing, approval, guest guide and staff pages, offline demo.
- api: [./api/README.md](./api/README.md) - Vercel functions (ES modules): public listing page with OG
  tags, listing import, Telegram bot, daily reminders cron, emails, KISA card payments.
- supabase: [./supabase/README.md](./supabase/README.md) - database patches, which of them are live
  (`APPLIED.md`), the generated schema snapshot, and Auth email templates.
- scripts: [./scripts/README.md](./scripts/README.md) - build scripts (asset stamping, sitemap) and the
  live schema dump.
- extension: [./extension/README.md](./extension/README.md) - Chrome extension that fills SS.ge and
  MyHome.ge posting forms from a listing.
- tests: Playwright e2e against a mocked Supabase (`tests/mock-supabase.js`, `tests/seed.js`) plus unit
  suites. Not a contract package.
- docs: strategy notes, audits and archived plans. Not code.

## Global Invariants

- Everything under `rigzea/` is public. No secrets in it; the anon key is public by design.
- Server secrets come only from Vercel environment variables (`.env.example` lists the names).
- Supabase URL and anon key reach every function through `publicConfig()` in `api/_lib.js`.
- All UI copy is Georgian and never uses the em dash character.
- Everything put into `innerHTML` is escaped with `esc()`; stored URLs in `href` go through `R.safeUrl()`.
- Database changes are new re-runnable `supabase/patches/NN_*.sql` files, dry-run on live inside a
  rolled-back transaction, applied only after the user agrees, then recorded in `supabase/APPLIED.md`.
- Edit only `rigzea/app/index.html`; the area pages are generated by `scripts/stamp-assets.mjs`.

## Global Side Effects

- Supabase Auth, PostgREST, Realtime and Storage (`rigzea-public`, `rigzea-private` buckets).
- Telegram Bot API, Resend email, KISA payments, Firecrawl (optional) from `api/`.
- Vercel cron calls `/api/cron-reminders/` daily at 05:00 UTC.

## System Verification

- Run: `npm test` (unit suites, all e2e, landing audit; about 10 minutes)
- Subset: `node tests/e2e.js <number>` runs only the e2e tests whose name starts with that number.
